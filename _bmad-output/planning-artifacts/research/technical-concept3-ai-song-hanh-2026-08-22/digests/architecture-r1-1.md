# Architecture patterns in practice — R1 digest

Scope: named-product AI teacher persona architectures; human-in-the-loop review patterns; continuous/proactive student monitoring patterns. Research firewall: findings below are limited to what was retrieved this run.

## Findings

- **Khanmigo (Khan Academy) is architected as a persona system prompt layered on stock GPT-4, not a fine-tuned model — "a chat-based AI tutor built on GPT-4, fine-tuned with system prompts" drawing on Khan Academy's library of 842 courses, with prompts like "You are an experienced math and science educator..." steering it to hold a Socratic-tutor persona.** [source: Tech & Learning (via aggregated web search snippet, original Sal Khan interview), accessed 2026-08-22, confidence: medium, class: architecture pattern] https://www.techlearning.com/news/what-is-khanmigo-the-gpt-4-learning-tool-explained-by-sal-khan
  - Note: not independently fetched/verified this round; corroborating snippet also surfaced via openai.com/index/khan-academy/ (OpenAI's own case study page) but that page was not fetched directly either — treat as a lead to confirm in a follow-up round.

- **Duolingo's "Lily" persona is built by feeding the LLM a persona brief (personality, speaking style, backstory, relationships to other characters) inside the prompt — i.e., prompt-engineered persona grounding on top of GPT-4, not a separately fine-tuned/voice-cloned model — and the persona is reused across many conversation contexts (roleplay scenarios like ordering at a café) with responses adapted to the learner's proficiency level.** [source: Duolingo Blog (blog.duolingo.com), accessed 2026-08-22, confidence: medium, class: architecture pattern] https://blog.duolingo.com/chatbot-language-practice/

- **Squirrel AI's adaptive-learning architecture is knowledge-graph-centric, not persona/chat-centric: it decomposes subjects into very fine-grained "knowledge components" (e.g., ~30,000 for junior-high math vs. ~300 coarse topics), links them into an evolving knowledge graph "iterated according to real learning data," and layers evolutionary algorithms, neural nets, and Bayesian networks on top to recommend next content and detect knowledge gaps in real time.** [source: HundrED Foundation profile of Squirrel AI Learning (via aggregated search snippet), accessed 2026-08-22, confidence: medium, class: architecture pattern] https://foundation.hundred.org/en/innovations/squirrel-ai-learning
  - A newer layer, described as a "Large Adaptive Model (LAM)," reportedly pairs the knowledge graph with an "MCM (Mode of Thinking, Capability and Methodology) graph" and is fine-tuned on ~24M students' / ~10B learning-behavior data points — this is a materially different pattern from prompt-only persona systems (Khanmigo/Duolingo) and worth verifying against a primary Squirrel AI source next round.

- **A recognized production failure mode of human-in-the-loop LLM review at scale is "fatigue of supervision": the reviewer isn't doing the generative work anymore but must hold the original intent in their head while auditing large volumes of mostly-correct AI output, which is described as cognitively harder than the work it replaced, not easier — and AI-assisted workflows have been observed to increase work *intensity* (constant iterate-review loops) rather than reduce it.** [source: Pydantic, "The Human-in-the-Loop is Tired" (Laura Summers), published 2026-02-18, accessed 2026-08-22, confidence: high, class: failure mode / post-mortem-style account] https://pydantic.dev/articles/the-human-in-the-loop-is-tired
  - Note: this article is about AI-generated code review (30 AI-authored PRs/morning for one developer), not education specifically — treat as an adjacent-domain analogy, not a direct EdTech finding.

- **A named architecture pattern for scaling human review of AI/agent output is "defense in depth" / layered review: automated evaluators triage the bulk of cases, a first-pass human reviewer handles routine issues, and expert humans do spot-checks — combined with prioritization/sampling that deliberately does NOT give equal scrutiny to everything, instead concentrating human attention on outliers (very long sessions, repeated tool failures, unusually costly traces, signs of user frustration).** [source: Comet, "Human-in-the-Loop Review Workflows for LLM Applications & Agents" (Dr. Cayla Eagon), published 2025-11-11, accessed 2026-08-22, confidence: high, class: architecture pattern] https://www.comet.com/site/blog/human-in-the-loop/
  - Same source names three complementary methodologies for where humans plug in: Active Learning (surface the most uncertain/risky/novel cases for human judgment — i.e., confidence-based escalation), Interactive Machine Learning (continuous real-time human-in-loop iteration), and Machine Teaching (using domain-expert input to reach good performance with fewer labeled examples).

- **A real (non-EdTech-specific) proactive/event-driven monitoring architecture for "at-risk" flagging follows: integrate multiple data feeds (LMS activity, SIS, attendance, advising notes, aid status) → define threshold rules → trigger real-time alerts → send automated first-line nudges → escalate unresolved/nuanced cases to a human. In this described pattern, automated nudges reach the student directly with NO human pre-approval step; humans are pulled in only after escalation, i.e., human-in-the-loop is applied to exceptions, not to every AI action.** [source: Element451 (Erin Newton), "Which AI Agents Help Nudge At-Risk Students Toward Success?", updated 2025-09-22, accessed 2026-08-22, confidence: medium, class: architecture pattern] https://element451.com/blog/which-ai-agents-help-nudge-at-risk-students-toward-success
  - This is the closest analog found this round to the "continuous supervision + proactive nudges" half of AI Song Hành, but it is a higher-ed advising/enrollment product, not a K-12 self-study tutor, and the source is vendor content (marketing register) — corroborate with an independent account before relying on it for a "no pre-approval" claim.

- **A described reference architecture for real-time student engagement tracking uses a streaming (not batch) pipeline: an event-transport layer moving learner activity to the platform near-real-time → a streaming layer that filters/joins/aggregates/enriches events → "decision services" that subscribe to events, hold per-learner state, and trigger downstream actions (must be low-latency to nudge a student while a live session is still active) → low-latency stores for dashboards plus separate longer-term analytical stores for historical data. The same source explicitly frames this as a move away from legacy batch ("data extracted once a day or once a week").** [source: 6B Education, "Event-Driven EdTech Development: Real-Time Analytics and Student Engagement Tracking", published 2025-11-17, accessed 2026-08-22, confidence: medium, class: architecture pattern] https://6b.education/insight/event-driven-edtech-development-real-time-analytics-and-student-engagement-tracking/
  - Named risks (not sourced to a specific post-mortem, presented as design cautions rather than reported incidents): intervention/alert fatigue if learners are bombarded with nudges; latency defeating the purpose of live-session interventions; possible bias against students with irregular usage patterns or poor connectivity. No named products, vendors, or documented real deployments were given in this article — treat these as design-stage warnings, not verified post-mortems.
